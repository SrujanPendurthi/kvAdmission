Why: recency is emergent, not chosen

Compression runs every chunk, so the cache never exceeds B + chunk and each round discards only chunk of B + chunk tokens. A fact planted at distance d must survive d/chunk rounds, and survival decays geometrically:

P(survive) = ( B / (B + chunk) ) d / chunk

The single-token model predicts the near band almost exactly and over-predicts the middle. Treating the fact as a multi-token span whose pieces must all survive flips the error the other way. The truth lies between, and the gap is informative: recent removes contiguous blocks so a surviving span survives whole, while random drops independently and fragments spans — which is why random now sits clearly below recent.

The qualitative claim holds: any policy that does not actively protect distant tokens decays into recency for free. A compression policy is not so much ranking tokens as rescuing them from an exponential already running.

What this licenses

A learned policy does not need to beat H2O at H2O's own game. It needs to reach the region where every existing method scores exactly zero — and on this task, at every budget tested, that region is a third of the context.

What this does not show

One model (Qwen3-1.7B) and one task. The needle setup is synthetic verbatim retrieval — the easiest possible case for a cache and the least like real long-context work — and recall is exact substring match, so a model holding the fact but paraphrasing counts as a miss. H2O and SnapKV are simplified reimplementations scored at token granularity across all heads, so their absolute numbers should not be compared to published ones. Terciles are coarse: "middle" spans d≈2731–5461, and a finer sweep would locate the boundary rather than assume a third.

The claim this supports is narrow: on this model and this task, no tested heuristic recovers mid-context information at any budget below full. Enough to justify building the learned policy. Not enough, alone, for a paper.
